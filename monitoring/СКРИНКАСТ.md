# Сценарий скринкаста на Mac

Ориентир — 3–5 минут. В этом задании достаточно показать запущенные Pod и доказать
сбор метрик. Устанавливать Helm-чарт во время записи не обязательно.

## Подготовка до записи

Запустите OrbStack/Docker и из корня проекта выполните:

```bash
minikube start
./scripts/minikube-build.sh
./scripts/minikube-deploy.sh
./monitoring/deploy.sh
```

Оставьте открытыми три отдельных Terminal с port-forward:

```bash
kubectl port-forward -n timepilot service/timepilot 8080:8080
```

```bash
kubectl port-forward -n timepilot deployment/timepilot 9090:9090
```

```bash
kubectl port-forward -n monitoring service/victoria-metrics 8428:8428
```

В четвёртом Terminal проверьте:

```bash
./monitoring/demo.sh
sleep 45
./monitoring/check.sh
```

Все пункты должны показать `OK`. Откройте в браузере
`http://127.0.0.1:8428/targets` и увеличьте шрифт Terminal до удобного размера.
Не показывайте содержимое Secret или личные API-токены.

Нажмите `⌘⇧5`, выберите запись всего экрана или области, при желании включите
микрофон через «Параметры» и нажмите «Записать».

## 0:00–0:40 — компоненты

```bash
kubectl get pods -n monitoring
kubectl get svc -n monitoring
helm list -n monitoring
kubectl get pods -n timepilot
```

Покажите VictoriaMetrics Running, Helm chart `victoria-metrics-single` и PostgreSQL
с двумя готовыми контейнерами (`2/2`: БД и exporter).
Пояснение: «VictoriaMetrics установлена Helm-чартом; её встроенный scraper собирает
метрики приложения и PostgreSQL каждые 10 секунд».

## 0:40–1:15 — OpenMetrics и Go runtime

```bash
curl -sS -D - -H 'Accept: application/openmetrics-text; version=1.0.0' \
  http://127.0.0.1:9090/metrics \
  | rg 'Content-Type|content-type|go_goroutines |go_memstats_alloc_bytes |process_resident_memory_bytes |timepilot_tasks_|# EOF'
```

Покажите `application/openmetrics-text`, Go/runtime/process-метрики, бизнес-счётчики
и `# EOF`. Поясните, что 9090 — внутренний порт и здесь используется административный
port-forward, а внешний Service приложения публикует только 8080.

## 1:15–1:50 — discovery и состояние таргетов

Откройте `http://127.0.0.1:8428/targets`: оба таргета должны иметь успешный scraping.
Покажите `timepilot-web` на 9090 и `timepilot-database` на 9187.

Вернитесь в Terminal:

```bash
kubectl get pods -n timepilot -o json | jq '.items[] | {pod: .metadata.name, annotations: .metadata.annotations}'
curl -fsSG http://127.0.0.1:8428/api/v1/query --data-urlencode 'query=up' | jq
```

Пояснение: «Адреса Pod обнаруживаются по Kubernetes API и аннотациям prometheus.io,
статических IP в конфигурации нет».

## 1:50–2:30 — PostgreSQL и сохранённые runtime-метрики

```bash
curl -fsSG http://127.0.0.1:8428/api/v1/query \
  --data-urlencode 'query=pg_up' | jq
curl -fsSG http://127.0.0.1:8428/api/v1/query \
  --data-urlencode 'query=pg_stat_database_xact_commit' | jq
curl -fsSG http://127.0.0.1:8428/api/v1/query \
  --data-urlencode 'query=go_goroutines{job="timepilot-web"}' | jq
```

У `pg_up` должно быть значение 1, а у остальных запросов — непустые результаты.
Это запросы к TSDB, значит данные уже собраны и сохранены, а не только доступны
на исходном `/metrics`.

## 2:30–4:10 — четыре бизнес-метрики

Покажите значения до операций:

```bash
curl -fsSG http://127.0.0.1:8428/api/v1/query \
  --data-urlencode 'query={__name__=~"timepilot_tasks_.*_total"}' \
  | jq '.data.result[] | {name: .metric.__name__, value: .value[1]}'
./monitoring/demo.sh
```

Пока проходит около 45 секунд, поясните четыре операции: создание, чтение одной задачи,
изменение, удаление. Счётчики учитывают только успешные операции и не используют
ID задачи в метках. Ожидание включает интервал scraping 10 секунд и стандартную
задержку видимости свежих данных в VictoriaMetrics (30 секунд). Затем:

```bash
curl -fsSG http://127.0.0.1:8428/api/v1/query \
  --data-urlencode 'query={__name__=~"timepilot_tasks_.*_total"}' \
  | jq '.data.result[] | {name: .metric.__name__, value: .value[1]}'
```

При одной реплике каждый из четырёх счётчиков увеличится на 1. Если приложение
масштабировано, значения принадлежат отдельным Pod; для суммарного результата
используйте `sum by (__name__) ({__name__=~"timepilot_tasks_.*_total"})`.

## Завершение и архив

Остановите запись кнопкой в строке меню macOS или `⌘⌃Esc`.
Просмотрите видео: команды и результаты должны быть читаемы.

```bash
./monitoring/package-submission.sh /absolute/path/to/screencast.mov
unzip -l timepilot-metrics.zip
```

Для сдачи приложите `timepilot-metrics.zip`. Видео, исходники, манифесты,
Helm values и отдельный `Отчёт.md` уже включены скриптом.
Остановите port-forward через `Ctrl+C` после записи.
