# Сценарий скринкаста SLI / SLO / SLA на Mac

Цель — показать именно **изменение графиков** при ошибках и восстановлении, а не
только список метрик или успешный curl. Ориентир — 5 минут.

## 1. Подготовка до записи

```bash
cd /Users/antonbarabulya/GolandProjects/timepilot
minikube start
./scripts/minikube-build.sh
./scripts/minikube-deploy.sh
./slo/deploy.sh
```

После уже выполненного развёртывания повторять сборку не нужно. Проверьте:

```bash
kubectl get pods -n timepilot
kubectl get pods -n monitoring
```

В двух отдельных Terminal оставьте port-forward:

```bash
kubectl port-forward -n monitoring service/victoria-metrics 8428:8428
```

```bash
kubectl port-forward -n timepilot deployment/timepilot 9090:9090
```

В третьем Terminal:

```bash
./slo/mode.sh healthy
./slo/check.sh
```

Дайте проберу около 150 секунд здоровой работы перед записью, чтобы графики
начинались с заполненного окна и 100%. Это время подготовки, не видео.
Если check сразу после старта пока не находит данные, подождите и повторите.

Откройте Markdown Preview файла [ГРАФИКИ.md](ГРАФИКИ.md). Откройте первые три ссылки
в отдельных вкладках браузера. Они ведут в установленную vmui на 8428:

1. Три SLI операций + цель SLO.
2. Внешний пробер + пороги SLO/SLA.
3. Соответствие порогам (0/1) на демонстрационном окне.

Если ссылка не сработала, откройте `http://127.0.0.1:8428/vmui/`, выберите Graph,
а запрос скопируйте из вывода:

```bash
python3 slo/graphs.py --query business_sli
python3 slo/graphs.py --query probe_sla
python3 slo/graphs.py --query compliance
```

Время просмотра — **Last 15 minutes**, шаг — **10s**. Именно относительное Last
15 minutes, чтобы при повторном выполнении запросов конец диапазона сдвигался к now.
Выберите автообновление каждые 10 секунд, если оно доступно, либо нажимайте
`Execute Query` каждые 10–15 секунд. Не используйте перезагрузку Pod как refresh.

Увеличьте шрифт браузера до читаемого размера. На видео должны быть видны график,
легенда с названиями серий и цели. Три SLI могут накладываться друг на друга,
поскольку общий отказ влияет на них одинаково: покажите значения каждой серии
в легенде/подсказке графика или отдельно в Table.

Нажмите `⌘⇧5` → запись экрана/области → «Запись». Голос необязателен, но следующие
короткие пояснения помогут проверяющему.

## 2. 0:00–0:40 — здоровый сервис и определения

Покажите первую вкладку: три SLI около 100%, линия SLO — 99.9%.

Пояснение:

> Используется Request Based SLO. Три счётчика успешных операций из прошлого задания
> делятся на число попыток. Для создания, чтения и обновления цель — 99.9% за 30 дней.
> В видео каждая точка считается за 2 минуты, чтобы увидеть изменения быстро.

Покажите вторую вкладку: показатель пробера около 100%, SLO 99.9%, SLA 99%.

> Пробер выполняет реальные запросы с тайм-аутом 2 секунды. Это внешняя относительно
> процесса проверка основного API. Предлагаемый SLA — 99% за 30 дней.

## 3. 0:40–2:10 — деградация

Переключитесь в Terminal и запустите:

```bash
./slo/scenario.sh
```

Скрипт сразу включает 50% ошибок на 90 секунд, затем сам восстанавливает приложение.
Оставьте Terminal работать и вернитесь к графикам.

> Приложение отвечает 503 на каждый второй запрос выбранных операций. Pod и /metrics
> остаются доступны. Количество попыток продолжает расти, доля успехов падает.

В течение следующих 60–90 секунд обновляйте графики. Чередуйте первую и вторую
вкладки. Покажите падение ниже порогов. В третьей вкладке флаги соответствия
переключатся с 1 на 0.

> Это нарушение порогов на коротком демонстрационном окне; месячный SLA по нескольким
> минутам данных не оценивается. Горизонтальные цели остаются неизменными.

Изменения видны с задержкой: scraping 10 секунд плюс около 30 секунд видимости
новых точек в VictoriaMetrics. Плавное падение вместо скачка — эффект окна 2 минуты.

## 4. 2:10–4:40 — восстановление

Через 90 секунд после запуска сценарий напишет `mode: healthy`. При необходимости
покажите сообщение в Terminal, затем вернитесь в vmui.

> Отказы выключены. Новые запросы успешны, но ошибки ещё остаются в скользящем окне.
> Поэтому SLI восстанавливается постепенно.

Обновляйте графики, пока линии не вернутся к 100% и compliance не станет 1.
На одном графике за Last 15 minutes будет виден весь путь: **100% → падение → 100%**.
Покажите вторую вкладку с обеими горизонтальными целями SLO и SLA.

Если после завершения сценария осталась одна старая точка, подождите ещё 10–15 секунд
и выполните запрос снова. Можно дополнительно проверить:

```bash
./slo/check.sh
```

## 5. Завершение и архив

Остановите запись кнопкой в строке меню macOS или `⌘⌃Esc`, проверьте видео и
сохраните на рабочем столе под именем `screencast.mov`.

```bash
./slo/mode.sh healthy
./slo/package-submission.sh /Users/antonbarabulya/Desktop/screencast.mov
unzip -l timepilot-slo.zip
```

Для сдачи — `timepilot-slo.zip`: отчёт в корне, скринкаст, код, конфигурация,
Kubernetes-манифесты и формулы. Скриншоты необязательны.

После записи отключите учебное управление отказами и остановите пробер командами
из раздела «Завершение демонстрации» в README. Остановка всего кластера при необходимости:

```bash
minikube stop
```

Закройте port-forward через `Ctrl+C`.
